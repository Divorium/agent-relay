This active ExecPlan records the repair of the real runner failure that remained after PR #44.

## Root Cause

PR #44 encoded an unverified assumption: the runner would contain only `/etc/containerd/config.toml.dpkg-dist`. Debian `dpkg` can use several temporary or backup suffixes during unpack and configuration, including `.dpkg-new`, `.dpkg-tmp`, `.dpkg-old`, and `.dpkg-dist`. Repeated interrupted attempts can leave more than the one sidecar generated by a clean forced recovery.

The prior test created a clean synthetic upgrade with force options from the beginning. It did not first fail at the interactive prompt, did not accumulate multiple sidecars, and explicitly called the cleanup helper before validation. It therefore proved the helper could delete the fixture it created, not that the production recovery path handled the real runner state.

## Decision Log

- Decision: remove every entry matching the exact managed-config prefix `/etc/containerd/config.toml.dpkg-*`.
  Rationale: these are inactive package-manager sidecars for the one configuration file fully managed by Agent Relay. The active `config.toml` is never removed.
  Date/Author: 2026-07-21 / implementation review.

- Decision: continue rejecting every other entry under `/etc/containerd`.
  Rationale: broad cleanup of the directory would hide unrelated or administrator-managed state.
  Date/Author: 2026-07-21 / implementation review.

- Decision: print each remaining unmanaged path before the existing strict validation error.
  Rationale: another failure must identify the real host state instead of forcing another filename guess.
  Date/Author: 2026-07-21 / implementation review.

## Idempotence and Recovery

Cleanup is idempotent. If no matching sidecars exist, no file is changed. Only paths beginning with the exact managed configuration path plus `.dpkg-` are deleted. The active `config.toml` and unrelated entries are preserved.
